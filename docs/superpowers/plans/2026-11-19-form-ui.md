# Form UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the interactive forms (`add`, `edit`, `copy`, `remove`, browse-launched) navigable like a settings screen: Esc cancels, ↑/↓ move between rows, single selects are one inline row, fields sit in titled sections with a theme and help footer.

**Architecture:** All changes are in `internal/tui/forms.go`. Each `Run*Form` is split into an unexported constructor that returns a fully styled `*huh.Form` (testable without a terminal) and the existing `runForm` that wires streams and runs it. A shared `styleForm` applies the keymap, theme, help and stack layout. The CLI and the `Run*Form` signatures do not change.

**Tech Stack:** Go 1.24, `github.com/charmbracelet/huh` v1.0.0, `bubbletea` v1.3.10, `bubbles/key`.

**Spec:** `docs/superpowers/specs/2026-11-19-form-ui-design.md`

## Global Constraints

- Stay on huh v1.0.0; no new dependencies, no huh v2 migration.
- Public API of `internal/tui` (`RunIdentityForm`, `RunProfileForm`, `RunCopyForm`, `RunRemoveForm`, all types) is unchanged; no edits under `internal/cli`.
- Esc aborts exactly like Ctrl+C: `runForm` returns `ok=false, err=nil` (it already maps `huh.ErrUserAborted`).
- Color rule (FR-042): forms use `huh.ThemeBase16()`; when `NO_COLOR` is set, `huh.ThemeBase()`. (Forms only open on a TTY, so `NO_COLOR` is the only remaining condition.)
- No em-dashes or en-dashes in titles, descriptions or comments.
- Commit trailer: `Assisted-By: 🤖 Claude Code`. Stage only the files named in the task; the working tree has unrelated uncommitted changes.

## Review Focus

1. **↓ on the very last field** must not submit the form (huh disables `Next` on the last field; Enter submits). Pinned in Task 2 (`TestProfileFormRowOrder` asserts `StateNormal` after walking past the end).
2. **Esc while a select's filter would be open** must still mean "cancel", never "clear filter". Filtering is removed by giving `Select.Filter` and `MultiSelect.Filter` a binding with no keys (huh re-enables a disabled `Filter` on every update, so `SetEnabled(false)` does not stick). Pinned in Task 1 (`TestFormKeyMap`).
3. **Harness without model, endpoint, auth kinds, share, hook sets or groups**: empty sections must be omitted, not rendered as a bare title, and ↓ must still walk every remaining field. Pinned in Task 2 (`TestProfileFormMinimalSections`).
4. **Pre-filled values on edit** must show in inline selects and survive ↑/↓ passes unchanged (only ←/→ change them). Pinned in Task 2 (`TestProfileFormInlineSelect`).
5. **Copy source with many profiles** stays a scrollable list: ↓ moves the highlighted profile, Tab leaves the field. Pinned in Task 3 (`TestCopyFormSourceList`).

- [ ] **Step 1: Write the test helpers and failing tests in `internal/tui/forms_test.go`**

The helpers drive a form without a terminal. huh moves focus through internal messages returned as commands, and some commands (cursor blink) block on a timer, so commands run with a short timeout:

```go
// drain runs cmd and feeds its messages back into f, recursing into batches and
// sequences. Commands that do not return within 20ms (blink timers) are dropped.
func drain(t *testing.T, f *huh.Form, cmd tea.Cmd, depth int) {
	if cmd == nil || depth > 30 {
		return
	}
	ch := make(chan tea.Msg, 1)
	go func() { ch <- cmd() }()
	var msg tea.Msg
	select {
	case msg = <-ch:
	case <-time.After(20 * time.Millisecond):
		return
	}
	if batch, ok := msg.(tea.BatchMsg); ok {
		for _, c := range batch {
			drain(t, f, c, depth+1)
		}
		return
	}
	if rv := reflect.ValueOf(msg); rv.Kind() == reflect.Slice { // tea.sequenceMsg
		for i := 0; i < rv.Len(); i++ {
			if c, ok := rv.Index(i).Interface().(tea.Cmd); ok {
				drain(t, f, c, depth+1)
			}
		}
		return
	}
	_, next := f.Update(msg)
	drain(t, f, next, depth+1)
}
```

`start` calls `drain(t, f, f.Init(), 0)`. `press` sends `tea.KeyMsg{Type: k}` per key through `f.Update` and drains the result.

Field keys (used by tests): `label`, `color`, `icon`, `model`, `endpoint`, `auth_kind`, `auth_key`, `herdr_agent`, `primary`, `share`, `hook_sets`, `exclude_hook_sets`, `history_group`.

Sections, in order (a section with no fields is not added):
